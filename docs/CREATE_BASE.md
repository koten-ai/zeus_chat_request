# Creating a new BASE pack (`base-N`)

> **Doc status** · last reviewed **2026-07-26** · production pin **base-1** · candidate pack **base-5** · prior candidate **base-4** · version matrix: [COMPAT.md](../COMPAT.md)


**Audience:** catalog authors, release train  
**Script:** [`scripts/new_base.py`](../scripts/new_base.py)  
**Text export (only):** [`scripts/export_base_text.py`](../scripts/export_base_text.py)  
**Pack verify (required after diet):** [`scripts/verify_base_pack.py`](../scripts/verify_base_pack.py)

A BASE **pack** is the on-disk ship unit under `v2/base/base-N/`.  
**Design docs** stay under `docs/` (do not copy BIBLE/ROADMAP into every pack).

---

## What a complete pack looks like (base-4 reference)

```text
v2/base/base-N/
  README.md                      # thin pack index → links to docs/
  OVERVIEW.md                    # short “what changed in this BASE” only
  MANIFEST.json                  # catalogs + paths + base_id
  response_output_schema.json    # Layer A machine schema
  response_output_example.json   # one valid terminate instance
  min/
    chat_request_<mode>_base-N.json   # × modes (analytics, auto, …)
  text/
    chat_request_<mode>_base-N.txt    # diet/edit working copies
```

| Artifact | Required? | Source when scaffolding |
| --- | --- | --- |
| `min/*.json` | **yes** | Copy from parent `--from` + rewrite `_lineage.base_id` |
| `text/*.txt` | **yes** | `export_base_text.py` |
| `MANIFEST.json` | **yes** | Generated by `new_base.py` |
| `response_output_schema.json` | **yes** | Copy from parent (edit later if Layer A changes) |
| `response_output_example.json` | **yes** | Copy from parent (edit later) |
| `README.md` / `OVERVIEW.md` | **yes** | Templates from `new_base.py` |
| Long design docs | **no** in pack | Live in `docs/` only |
| Migration hop | **yes** for real bumps | `docs/migration/base-X_to_base-Y/` + **RELEASE_CHECKLIST.md** |

## One command (preferred)

From repo root:

```bash
# Scaffold base-5 from base-4 (copies min JSON, schemas, exports text, MANIFEST, README, OVERVIEW)
python3 scripts/new_base.py --from v2/base/base-4 --base 5

# Dry run
python3 scripts/new_base.py --from v2/base/base-4 --base 5 --dry-run

# Prototype pack name base-5-prototype
python3 scripts/new_base.py --from v2/base/base-4 --base 5 --prototype-pack

# Text only (no min JSON copy) — legacy helper
python3 scripts/export_base_text.py --from v2/base/base-4/min --base 5
```

### What `new_base.py` does

1. Creates `v2/base/base-N/` (fails if non-empty unless `--force`).  
2. Copies `min/chat_request*.json` from parent `min/` (or parent itself if it *is* the min dir).  
3. Rewrites `_lineage.base_id` → `base-N`, file stems, `_note` doc pointers.  
4. Copies `response_output_schema.json` + `response_output_example.json` when present.  
5. Runs the same text export path as `export_base_text.py` → `text/*.txt`.  
6. Writes **pack** `MANIFEST.json` (schema_version 2, catalog list + doc paths).  
7. Writes thin `README.md` + `OVERVIEW.md` templates.  
8. Does **not** invent `contract_hash` or stamp.  
9. Does **not** copy BIBLE/ROADMAP into the pack.

### What you do after scaffold

**Scaffold ≠ ship.** Parent wire is copied until you diet. Phases A–G live in the master checklist.

**Master list:** copy [migration/RELEASE_CHECKLIST_TEMPLATE.md](migration/RELEASE_CHECKLIST_TEMPLATE.md)  
→ `docs/migration/base-X_to_base-Y/RELEASE_CHECKLIST.md` and check every box.

```text
1. Diet / edit catalogs (text or JSON) for the BASE theme
2. If Layer A changed: edit response_output_schema.json + example; keep in sync with return tool params
3. Re-export text if you edited JSON:
     python3 scripts/export_base_text.py --from v2/base/base-N/min --base N --out v2/base/base-N --no-set-base-id
4. Refresh MANIFEST:
     python3 scripts/new_base.py --refresh-manifest --base N
5. Scan inspector index:
     python3 scripts/scan_catalogs.py
6. VERIFY (P0 — fail = do not open pack PR):
     python3 scripts/verify_base_pack.py --base N
7. Fill hop RELEASE_CHECKLIST + GUIDE (+ lessons)
8. Update ROADMAP + RELEASE_NOTES + COMPAT + BASE_AGENT_PLAYBOOK
9. Diff in index.html (parent mode vs new mode)
10. Jira / CR board (Phase J — required after pack ship):
     update base-N epic + create residual Client/Zeus stories;
     link blockers to pin epic; see RELEASE_CHECKLIST §9
11. Client spike + stamp path before CURRENT pin
```

See [BASE_AGENT_PLAYBOOK.md](BASE_AGENT_PLAYBOOK.md) · base-4→5: [migration/base-4_to_base-5/RELEASE_CHECKLIST.md](migration/base-4_to_base-5/RELEASE_CHECKLIST.md).

## Docs vs pack (do not mix)

| Change type | Edit |
| --- | --- |
| Prompt construction, rules objects, settings, ownership | `docs/*.md` |
| Migration story for this bump only | `docs/migration/base-X_to_base-Y/` |
| Verb text, Terminate table in system prompt | `v2/base/base-N/min/*.json` (then re-export text) |
| Layer A field machine schema | `v2/base/base-N/response_output_*.json` **and** return tool parameters in min JSON |
