================================================================================
1. WHAT IS IN THE CATALOG FILE vs RUNTIME
================================================================================

  IN FILE (chat_request*.json)
    _format, _version, _hash, _hash_policy, _note, _lineage
    contract { builder, hash, … }
    messages[0].content     = system / how Zeus works
    verbs[13]               = tools
    (full) instructions, masq, guidance, metadata

  RUNTIME (not baseline file)
    SCOPE BRIEF + MINI-SCHEMA
    zeus_client.business_injection (messages + rules object + optional output_request)
    session round/turn
    user message, tool results
    AgentHooks effects

  TERMINATE (model → Client splits audiences)
    G1 summary, confidence, decomposition fields
    G2 subject_confidence, wish_i_knew, jail_break_attempt (admin)
    G3 business_rules_triggers (base-5: { id → bool }) + optional app_output

================================================================================
2. CONTRACT vs CLIENT (hash boundary)
================================================================================

  HASHED (re-stamp if changed)
    Base-n body, verbs, weight order, response schema, hard flags,
    allowed/denied verbs when locked

  NOT HASHED (Client / tenant pass-in)
    brand boilerplate, business_injection.rules (named object), output_request,
    locale, SCOPE BRIEF, MINI-SCHEMA, user text, soft guidance

  Why: tenant copy and live schema must not thrash production stamps.

================================================================================
3. TOKEN BUDGET
================================================================================

  Min catalogs ~13–17KB. Assembled prompt grows with inject + history + tools.
  Prefer short named rules + sparse trigger objects over 60KB policy novels.
  Drop soft guidance first; keep verb surface + terminate schema + hard flags.
  See PROMPT_ASSEMBLY.md, RULES_OBJECT_AND_OUTPUT_REQUEST.md, simple_layout.txt §N.

================================================================================
4. ORIGINAL SKETCH — RIGHT vs WRONG (history)
================================================================================

RIGHT
  - System "how Zeus works" + ~13 APIs + priority + hash + user separate
  - Mini-schema and business text appear in the AI-facing payload

WRONG / imprecise
  - No physical #B-{INT} markers — system lives in messages[0].content
  - Hash is _hash_policy.pointers, not "md5 of all injects"
  - 13 are VERBS, not "13 instructions"
  - Jailbreak score is terminate admin 0.0..1.0 subjective, not catalog prose alone
  - wish_i_knew is per-turn admin gap report, not catalog facet wishlist
  - Mini-schema is runtime inject, not inside Base blob for hashing

MISSING from first sketch (now in simple_layout / PROMPT_ASSEMBLY)
  - Envelope, lineage, min vs full, soft guidance
  - Contract vs Client ownership
  - G1/G2/G3 terminate split
  - business_rules_triggers (named object in base-5) for round control
  - output_request / app_output for Client-specific structure
  - brand message_failure boilerplate
  - token budget discipline
