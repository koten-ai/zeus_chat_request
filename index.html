Simple picture: how it fits together

          
You ask a question
        │
        ▼
  Zeus Client (or Hub chat)
        │  1) load chat_request_*.json  (this file = menu + house rules)
        │  2) inject BLUE pieces: scope brief, mini-schema, business rules, your message
        │  3) call the LLM with tools (verbs)
        │  4) LLM calls Zeus APIs (find / search / pipeline / …)
        │  5) LLM terminates with STANDARD output fields
        ▼
  Answer + query_decomposition (for analytics) + refs

          
This repo holds baseline templates (by mode). Your production file is refined in Hub Workbench and stamped on your Zeus so the hash matches what you deploy.


          
Color policy (cards = tree)

          
    
            
  • RED — Rules. Shipped in the catalog; changing them changes the contract hash. Edit only via Zeus generator / deliberate release.
    • 
            
  • GREEN — Editable guidance. Business-friendly advice (optimal paths, facet docs). Hash-excluded on full profiles. Often missing on min (yellow card).
    • 
            
  • BLUE — Injected at runtime by Zeus Client / Hub (not stored in the baseline JSON). Competes for tokens with the red system prompt.
    • 
            
  • PURPLE — Meta / stamp labels (id, hash, notes).
    • 
          


          
Glossary (plain language)

          

            

              
chat_request*.json

              
The menu + house rules the AI sees: which tools it may call and how to answer. One file per mode.

            

            

              
Rules (hashed)

              
Parts that define “what production promised.” If they change, the contract hash changes. Clients bind that hash so nothing drifts silently.

            

            

              
Guidance (editable)

              
Hints for the model (paths, examples, business tone). Usually not in the hash so you can tune without breaking every client binding.

            

            

              
Contract / stamp

              
Server-issued fingerprint of the rules. Production: verify/stamp on your Zeus, then clients send contract_id + contract_hash every turn.

            

            

              
verbs / tools

              
Functions the model is allowed to call (find, search, pipeline, return, …). No verb ⇒ model can’t use that capability safely.

            

            

              
MINI-SCHEMA / scope brief

              
Live description of your data (entity types, fields, counts). Injected so the model doesn’t invent columns. Comes from Zeus for the bound scope.

            

            

              
Business rules / prompt_override

              
Your company language and policies (“always use our product names”, “never invent prices”). Injected by Hub/Workbench or client config—not hard-coded forever into the public baseline.

            

            

              
query_decomposition

              
Structured intent facets the model must return on finish (e.g. intent=Best, entity=Hotel). Powers hot-path analytics / Compare—not just pretty text.

            

            

              
decomposition

              
Data extraction shape grounded in MINI-SCHEMA (targets, predicates, output type). Helps routing and verification.

            

            

              
min vs full profile

              
min (this repo) = smaller payload, verbs + system rules kept, bulky guidance often stripped. full = engine Hub snapshots with full guidance/instructions.

            

            

              
Standard output schema

              
Every terminating return / pipeline uses the same required fields across modes and deployments: summary, query_decomposition, decomposition, confidence. That standardization lets analytics and clients parse every call the same way.

FAQ

          
What is the difference between AUTO, ANALYTICS, FRAUD, … in the dropdown?

          
Each file is a mode profile: same idea (tools + rules), different emphasis.

          
    
            
  • analytics — default “real links, not noise”; balanced graph + semantic tools.
    • 
            
  • auto — discovery / safe-during-setup; not a long-term production mode.
    • 
            
  • fraud — keep more “noise”; lower confidence floor; graph structure matters more.
    • 
            
  • code / research / open — more exploratory or code/doc oriented tool mix.
    • 
            
  • tenant / private / regulated — stricter tenancy / compliance posture in the product stack.
    • 
            
  • custom — placeholder for operator-tuned modes.
    • 
          

          
The dropdown only switches which baseline you inspect. Your product picks a mode per scope in Zeus.


          
Where do I put “talk about my business” for the AI?

          
    
            
  1. Hub Workbench / scope config — business injections, prompt overrides, entity map language (preferred).
    2. 
            
  2. guidance on a full catalog (optimal_paths, notes) — green / editable, hash-excluded.
    3. 
            
  3. Not by hand-editing red messages/verbs in this public baseline if you care about stamp/hash stability—use the Zeus generator + Workbench, then stamp.
    4. 
          


          
How do I optimize chat_request?

          
    
            
  1. Use Size map: shrink what dominates tokens (usually system prompt + tools).
    2. 
            
  2. Prefer min for clients; keep evidence-loop terminate fields.
    3. 
            
  3. Push domain knowledge into MINI-SCHEMA + blue injects, not a 50-page system essay.
    4. 
            
  4. Use pipeline / cheaper verbs; don’t expose tools you don’t need for that mode.
    5. 
            
  5. Stamp on Zeus; A/B with eval packs before swapping production hashes.
    6. 
          


          
What is “schema output standardization”?

          
No matter which mode or which deployment, when the model finishes a turn it must emit the same structured envelope (at least):

          
    
            
  • summary — human answer facts
    • 
            
  • query_decomposition — business intent facets (intent + entity + …)
    • 
            
  • decomposition — data targets/predicates from MINI-SCHEMA
    • 
            
  • confidence — string high|med|low only
    • 
          

          
That way every call, every environment, can be logged, compared, and fed into hot-path analytics the same way. See the green “Standard output” panel on the Cards tab.


          
Why is guidance yellow / missing on min?

          
Min profiles drop bulky green guidance to save tokens. Rules (red) + injects (blue) still run. Put durable business policy in Hub injects; use full profiles when you need green optimal_paths in-file.


          
Can I edit the JSON in this repo by hand?

          
Baselines are generated in Zeus (make ai-snapshot-min) then published here. Prefer editing Zeus prompt fragments / generator, regenerate, publish—don’t maintain a second hand-edited truth.
